# Architecture

The local chess stack depends only on python-chess, PyTorch, NumPy, and configuration. `core.py` encodes a board and maps legal moves to policy indices. `model.py` predicts policy logits and a side-to-move value. `search.py` masks to legal actions and runs policy-only or PUCT search. `data.py` streams PGN into game-level splits. `teacher.py` runs Stockfish offline to label existing positions. `training.py` consumes JSONL examples and writes checkpoints and metrics. `validation.py` measures held-out fit; `self_play.py` makes local student-only training targets; `evaluation.py` plays local baseline games. `engines.py` isolates explicit external UCI opponents. `experience.py` keeps assisted games in SQLite and provides post-game annotations and weighted training exports.

The teacher and engine modules are never imported by student search. The assist CLI currently observes local games only. A future browser adapter will consume the same `chess.Board`, student search, and experience API after verifying a bot-only game. See [Chess.com boundary](CHESSCOM.md) and [assist mode](ASSIST_MODE.md).
